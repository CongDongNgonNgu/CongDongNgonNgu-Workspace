Response must belong to that parent, match kind, be ACTIVE with active verified author, and parent must be current/readable. One active acceptance per parent enforced by partial unique index and composite response/parent FK. Existing transaction locks parent then response; same response retry returns existing acceptance, replacement revokes old acceptance and invalidates related Library candidate, unaccept is idempotent, reaccept creates new acceptance episode. Acceptance does not verify content or publish it to Library; candidate nomination remains existing separate requester/public/accepted/review flow.

Hidden/deleted/inactive response is not eligible for answered/accepted categorization; UI must not display its accepted badge or content. Existing moderation setter invalidates candidates but retains acceptance row; search must JOIN eligibility rather than count acceptance rows alone. Existing service eligibility prechecks are not repeated fully inside acceptance SQL locks: this is a recorded later002 regression/hardening gate, not proven race-safe acceptance today.
