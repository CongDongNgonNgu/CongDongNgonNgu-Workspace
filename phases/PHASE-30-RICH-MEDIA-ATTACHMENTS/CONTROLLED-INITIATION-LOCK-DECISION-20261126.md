# Controlled INITIATE continuation lock decision

Date:2026-11-26. Status:ACCEPTED_SOURCE_ONLY_AFTER_INDEPENDENT_ARCHITECTURE_REVIEW. Authority: active Phase30 implementation scope and standing reversible source workflow; this is an engineering decision, not owner approval of runtime/provider activation or acceptance. Phase30-002 remains IN_PROGRESS/REMEDIATE_AND_RETEST.

The historical REQUEST-ADMISSION-PHASES-002-20261111.md Phase2 required releasing diagnostic locks before ordinary account/domain locks. That remains the binding transaction rule: coarse reservation and matched ownership/burn commit independently before any product mutation. It is insufficient as a continuation rule because a separate fresh-check/release/write sequence allows original run closure, expiry or request cancellation between the check and product SQL.

Decision: only explicitly injected controlled INITIATE reacquires exact original run, request attempt and bound-operation locks, in that order, before each of its two SQL transactions. RATE then uses existing immutable admission and sorted rate counters and commits separately; it never acquires account/scope/attachment locks. DOMAIN reacquires the same ledger order before existing account/scope/admission/attachment and capacity work on the same PoolClient. The original private context is issued once and consumed synchronously before await. Native cancellation and original SQL time/control/binding facts are checked after lock waits and before callbacks; RATE and DOMAIN check again before their independent COMMIT. DOMAIN also checks after fresh authorization waits, around INSERT/replay and before returning. Closed callback helpers cannot be reused. Existing bounded lock/statement timeouts remain; no callback performs network/provider work or opens another transaction.

This narrowly supersedes the release-before-domain clause only for the later controlled INITIATE continuation. Ordinary initiation, quota/ACL rules, matched ownership COMMIT, durable burns, generic binding and all other operations keep their existing contracts. It authorizes no DDL install, runtime composition, global worker, provider call or Production change. Future controlled producers must receive their own reviewed lock and lifetime contract.

Alternatives rejected: a transferable fresh token becomes stale after release; retaining unchecked ordinary initiation permits random IDs or delayed product writes; changing the entire run-state protocol or duplicating domain logic creates a larger correctness surface. Reuse the existing rate/domain bodies under trusted callbacks with fresh exact ledger fences instead.

Independent architecture review explicitly accepted this source-only exception after inspecting lock order, private context, cancellation, ordinary rejection and same-client callbacks. SQL time checks prove mutation admission/final pre-COMMIT validity; they do not prove COMMIT acknowledgement arrives before expiry. Uncertain/late acknowledgement or cancellation may leave durable state without success, never issue reconstructed authority or refund burns.

Evidence so far: corrected-source controlled-domain SQL9/9 in81.147s, including actual writer blocking followed by natural expiry before callback continuation; native HTTP SQL RED1failed8passed (ordinary disabled adapter substitutes for controlled producer), then GREEN9/9 in50.45s with real native session/CSRF/parser/pinned binder/SQL repository/current metadata ACL. The positive fixture repository explicitly enables IMAGE while ordinary runtime/config remain four-false; no provider is called. Admission343/343 and focused27/27, default HTTP20/20 and type/lint/build passed. These are source/owned-random-schema proofs, not actual deployment/resource/retention acceptance. Globally unique burned IDs cannot be redeclared; current exact-ID replay proof starts from an ordinary preexisting draft. Controlled-created retry allocation remains a separate unresolved contract.

Mandatory follow-up before actual runtime: post-repository AttachmentReadService metadata read-rate charging and ACL projection currently remain ordinary transactions outside this original-window fence. This accepted source decision covers the initiation RATE/DOMAIN bodies only. A closed internal continuation must fence those later stages without bypassing native token/session refresh, current metadata ACL or normal read-rate policy. Expiry/cancellation after committed INSERT may leave the exact row without success; it must not authorize later SQL outside the run.
