## A. Entity and binding

Propose attachments(UUID, uploader, state, expected bytes/type, detected type, checksum, immutable opaque storage key, safe filename, caption/alt text, processing version, expiry, rejection code, timestamps). Separate provider object/version information from serialized DTOs. Store parent links in a separate attachment_bindings table: each binding row has exactly one non-null Community post, Study Group text or direct message FK, plus a unique attachment ID. Unbound draft uploads have zero binding rows; committed content attachments have exactly one. Real foreign keys and transactional association enforce this without forbidding draft states. Never use a free-form polymorphic ID without relational integrity. Draft uploads have an intended server-validated domain scope and no recipient read grant. Association is transactional with content creation and current write authorization; ready bytes alone do not mean a message/post was sent. One file cannot be rebound, shared across privacy domains or publicized through a reference.

## B. Storage port

Provider-neutral port: putTemporary(bounded stream, immutable key, checksum), head(key), openRead(key, bounded range), delete(key), listOwnedPrefix(prefix,cursor), health/capabilities. No caller-provided bucket, URL, filesystem path or object key. R2 implementation reuses existing SDK, but never the backup client's broad operational responsibilities. Disabled and deterministic in-memory test adapters are explicit; neither can satisfy deployed persistence acceptance. Keys use random IDs under a media-only namespace; filenames never determine paths. Existing backup namespace remains untouched. Prefer a separately approved private TEST media bucket and scoped credentials; existing bucket reuse requires explicit privacy/scope verification. Prefixes alone do not provide permission isolation.

## C. Upload protocol and interface proposal

Base /api/v1/attachments; normal access guard and cookie CSRF on writes; existing success/error envelope. Initiation accepts a typed intended scope, filename, declared MIME, byte count and client idempotency UUID; returns attachment ID, state, expiry and bounded authenticated upload route, never a public URL. Raw upload uses a bounded streaming route; no unbounded memory multipart buffer or base64 JSON. Enforce actual transferred bytes even with missing/false Content-Length; stop oversized streams. Reject arbitrary remote URL import. Finalize locks attachment and parent/scope under the domain lock order, rechecks ownership/current write permission, validates durable bytes and checksum, and schedules bounded inspection. Replays of same key/payload return same result; conflicting metadata returns409. Duplicate finalize cannot run parallel processors or duplicate bindings. Bound-object HEAD/metadata/read/range/preview/delete all reauthorize their exact parent. Unbound draft initiation/upload/finalize/cancel and sanitized status metadata require both the uploader identity and freshly authorized intended write scope; no server draft-byte/thumbnail read route or recipient visibility is granted before binding. Local picker previews are untrusted local UI only. Revoked drafts expire through cleanup without restoring access. opaque404 unavailable for missing/foreign/denied objects, normal401 for unauthenticated requests. Use typed bounded DTOs and safe stable error codes; no object keys, internal reasons, tokens or private bytes in errors/logs.

## D/E. Content validation and pending limits

Candidate formats only: decoded/re-encoded JPEG/PNG/WebP images; inspected MP4 with explicitly approved codecs; UTF-8 plain text and strictly inspected PDF downloads. No candidate is approved yet. PDF active actions/embedded files/JavaScript/encryption and malformed structure require rejection; if reliable bounded inspection is unavailable, PDF stays unsupported. Deny SVG/HTML/XML, executable/script/archive/Office macro types and unknown formats. Video/audio codec and container validation must exceed an ftyp signature. No extension-only, MIME-only or magic-only acceptance. Corrupt/polyglot content must fail closed; use complete vetted parsing, normalized derivative output where appropriate and disallow unsafe inline original rendering. This is not a malware-free guarantee.

Numeric upload bytes, decoded pixels, dimensions, duration, frame rate, per-content count, actor retained bytes, daily bytes, concurrent upload/processing, wall-clock timeout and parser-memory limits are UNAPPROVED. Derive them from a verified transport/processor measurement on the actual TEST plan and review them before freeze. The observed512MB/0.1CPU plan is a resource constraint, not evidence for an arbitrary media limit. No processor/service is silently activated to make video work. Unsupported or unavailable inspection stays rejected/pending, never ready.

## F. State machine

TEMPORARY (reservation) -> UPLOADING -> PENDING (durable received, quarantine/inspection) -> READY or REJECTED. TEMPORARY/UPLOADING/PENDING/READY/REJECTED may transition to DELETED via authorized lifecycle/expiry; DELETED is terminal and unreadable. READY means validated available bytes, not an unbound draft visible to recipients. Store conditional state/version and processing lease; retries cannot revive a tombstone. Missing object/read failure returns generic unavailable; it does not manufacture successful persistence. Processor timeout/rejection never publishes original bytes.

## G. Fresh reads and revocation

Select authenticated backend proxy reads for private bytes and all previews/ranges/metadata. Every request uses current account/session and exact owning-domain authorization; uploader ownership cannot bypass revoked membership/connection. Community reads follow current parent visibility/moderation/author/language eligibility. Group reads follow current ACTIVE membership, group lifecycle and hidden-text role rules. DM reads follow the exact canonical eligible connected pair and absence of either-direction block. Membership grants no DM rights, connection grants no group rights, reference grants no file rights. Same private storage and proxy policy can serve public Community after current public-eligibility check, avoiding sticky public object URLs.

Use private,no-store and nosniff; safe content disposition with server-normalized type; documents always download, no embedded document viewer. Only validated normalized image/video derivatives can be inline. No service-worker/shared cache persistence. Frontend clears bytes/object URLs/previews/uploads on identity/route/access loss and rejects late responses by generation. Revocation linearizes with current domain authorization/attachment-state check under existing account->group or account/pair->conversation lock order, before response admission. Do not hold DB locks over unbounded network transfer; already admitted/in-flight bytes and downloaded copies cannot be recalled. Future requests after revocation deny. Review any cross-domain lock acquisition separately to avoid inversion.

Provider-signed GET URLs are bearer credentials: expiration bounds future requests using that URL, not copies already downloaded, cached responses, or necessarily an already-started transfer. Revoking app membership alone cannot revoke an outstanding independent storage URL. Therefore do not issue provider-signed private GET URLs. If short-lived app read tickets are later necessary, require current authenticated actor/domain checks on every redemption, including ranges; ticket possession is never authorization.

## H/I. Lifecycle and abuse

Delete commits a tombstone first, denying future reads before physical removal; durable cleanup jobs retry exact keys/version and derivatives idempotently. Crash between DB/storage actions is expected: reconcile expired reservations, abandoned uploads, rejected bytes, missing ready objects and unbound orphans. Persist job lease/attempt/backoff and bounded scans; no unsafe bucket-wide deletion. Account for reserved bytes atomically before upload, actual bytes at finalize, and retention until verified physical deletion; failed attempts still consume rate allowance. DB-backed actor/action counters must work across replicas and restarts. Existing group/message text quotas remain intact. Cleanup must be executable on Render Free without reliance on unavailable one-off jobs; select an approved bounded scheduler mechanism before freeze. Storage errors retry safely, never relax ACL or claim cleanup success. No retention/erasure SLA promised before a reviewed policy.

## J/K. Presentation and moderation

Safe bounded Unicode display names, strip path/control/bidi hazards for download names, preserve meaningful display text with wrapping; encode all output, never interpolate into headers. Caption/alt metadata is plain text with reviewed length bounds, not trusted HTML. Strip EXIF/GPS/private metadata from inline derivatives; original download privacy must be explicit. Use generic unavailable/document/video fallback without unvalidated thumbnails. All derived objects inherit exact parent ACL. Quarantine hooks fail closed on unavailable/error; hooks are not a staffed moderation or antivirus guarantee. Parent authorization policy dominates child availability: deleted/archived parents deny; hidden Study Group texts retain current scoped OWNER/MODERATOR read authority and deny ordinary members. Record safe reason codes, never full filenames/bytes/tokens in operational logs.

## L. Cross-surface and lifecycle exclusions

See CAPABILITY-MATRIX-001.md. A single shared service/port and UI upload hook owns protocol/lifecycle. Context-specific cards do not duplicate transport. Community corrections retain immutable original/context and separate proposal/explanation. No attachments under structured responses, ordinary comments or learning-reference payloads are implicitly granted. Group text and DM bodies remain immutable; propose attachment-only tombstones for author removal while currently authorized, without new text edit/delete semantics. Freeze role-specific hide/removal and parent-edit transactions before implementation.

## Migration and rollout strategy

Additive migration after001 freeze only: attachment/binding/cleanup/rate tables and constrained indexes, no destructive backfill or alteration of canonical text. Respect next actual migration ordinal/checksum and domain FK patterns; do not reserve a guessed ordinal now. Validate SQL constraints and up/down in disposable schema; verify exact approved TEST target and ledger before applying. Production DB untouched. Old API clients continue without optional attachment references; rollout feature disabled until storage, validation and authorization gates pass. Rollback disables new writes/reads safely and retains metadata/blobs for reconciliation; never run destructive down against shared TEST data. Recheck existing domain tests and dependency/security gates.
