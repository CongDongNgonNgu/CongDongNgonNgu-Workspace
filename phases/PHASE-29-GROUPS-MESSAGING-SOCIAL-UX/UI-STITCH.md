## Refinement and exclusion decisions

Initial designs were independently rejected/refined for fabricated cohort metadata, roles, counts, schedules, honor-code/legal commitments, developer simulation switches, secret recovery, reply/media/presence features, dense prose and mixed locales. A desktop information refinement had visibly overlapping columns and was rebuilt again. Preserve these truthful review records; do not label rejected screens as selected.

The initial desktop held-target request returned a textual contract assessment rather than a screen. A separate actual fallback screenshot was then generated. Its note is design documentation only. Stitch's textual assessment is not evidence of backend capability or current product runtime.

Some initial batch prompts lacked their shared prefix due asynchronous orchestration state; subsequent refinements supplied the full project palette/contract explicitly. Existing project tokens and source contracts always override generated design-system defaults. No alternate generated Material palette, foreign font/icon family or new framework is approved.

Mandatory exclusions: public group search/join/preview, structured group learning metadata, invented activity/member counts/global unread totals/message previews, presence/typing/partner receipts, independent group-conversation controls, media/voice/files/calls, reactions/replies/edit/pin/mute/search/filter capabilities absent from API, fixed/stored invitation secrets, hidden-role escalation, inline technical manifests, new honor-code acceptance or academic-course assumptions. Never render sample names/messages/counts in product empty/error states. Use actual server state only.

Keep native one-use/manual invitation acceptance with group ID plus secret; the pictured one-field acceptance panel is excluded. Owner transfers before leave; moderator cannot invite/elevate/remove peers. Native role-appropriate reports/moderation/pagination remain even if a reference omits them. Context cards use real resolver output and never grant authorization. No group preview/management inside direct-conversation information.
