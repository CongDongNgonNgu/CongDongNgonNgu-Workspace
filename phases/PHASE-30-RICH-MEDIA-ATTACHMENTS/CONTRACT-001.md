## Entity, transaction and domain binding

One attachment entity holds UUIDv4/uploader/scope and scope-generation, state/version, expected/detected type and bytes, checksum, safe metadata, private generated object references, expiry/lease/rejection reason/timestamps. Provider fields never enter DTOs. Permanent firstBoundAt prevents reuse after a binding is removed. Typed attachment_bindings has one attachment ID unique and exactly one parent FK (Community post, group text, direct message). Group/text and conversation/message composite FKs ensure exact scope; add UNIQUE(conversation_id,id) to direct_messages if needed. No unchecked polymorphic parent IDs. Drafts have zero bindings; an attachment can bind only once for its lifetime. Parent deletion makes binding unavailable immediately; any FK-cascade removal must leave cleanup responsibility durable, with formerly-bound metadata never becoming a reusable draft.

Immutable intent is COMMUNITY(postType,languageId,visibility), STUDY_GROUP(groupId,membershipGeneration), or DIRECT_MESSAGE(conversationId,current CONNECTED language_exchange_connections.id UUID). Creation/finalize/binding requires uploader ACTIVE/verified plus current domain write permission and matching intent/generation. Leaving/rejoining must not revive stale drafts. DM disconnect/block deletes the connection row; unblock does not restore it and reconnect creates a new UUID. Capture the CONNECTED row ID through the same PoolClient under lockMessagingPair locks and compare it exactly at upload/finalize/READY/binding; missing/different UUID permanently invalidates the draft. Retain this UUID as scope evidence without a cascading FK to the removable connection row. No new connection-generation column is required; updated_at is not the fence. Already-bound attachments keep existing current pair/conversation authorization, including historical access after eligible reconnect if Phase26 permits it. Temporary account/preferences/contact ineligibility still denies fresh operations, but the connection UUID does not record transient history unless the row is deleted. Ready unbound bytes grant no recipient access and no server-side draft-byte/thumbnail route. Local picker previews are untrusted UI only.

Internal binding port accepts existing PostgreSQL PoolClient. Parent insert/edit and ordered attachment binding commit atomically; no second pool connection or post-commit association API. Parent author must equal uploader. Validate duplicate IDs, READY/unexpired state, scope, format capability, ownership, count/source-byte total and never-bound condition for newly added attachments under sorted attachment locks. Community edits may retain/reorder/metadata-edit existing live bindings to the SAME parent without changing firstBoundAt; foreign, removed, deleted or previously detached bindings cannot be reused. Invalid binding rolls back parent insert/edit. Group/DM original ordered IDs form an immutable send fingerprint beside existing text/context/client_message_id; retry after removal returns original send plus current safe projection, never restores metadata/content or changes retry identity.

Lock order is domain before attachments: ordered user accounts; then group lock/current ACTIVE membership or canonical pair eligibility/advisory lock and conversation lock; then sorted attachment IDs; then all actor-quota rows sorted by actor/action/window, IP-quota rows sorted by trusted IP/action/window if applicable, deployment-quota rows sorted by action/window, and finally the singleton processing-lease row. All initiation/binding/deletion/reconciliation byte-reservation changes use this same order. Rate admission may run in a separate short transaction that touches only sorted actor, IP then deployment rate rows, commits/releases them before domain authorization and never later acquires account/domain/attachment locks. Quota/lease-only maintenance releases those locks before entering domain order. No processor holds SQL locks while performing I/O. Community requires transaction-aware repository executor: current author/account and exact parent row/active language checks with existing moderation/visibility rules, then attachments. Corrections create parent+canonical correction+binding in the same existing transaction; question creation uses the same executor. Do not acquire account/domain locks while holding cleanup/attachment locks. Lease a cleanup candidate, release selection locks, then enter ordinary domain order and recheck version/state. Independent concurrency tests must prove this ordering against existing domain writers before acceptance.

Group ACTIVE membership alone never grants DM rights; direct connection never grants private-group rights. Group archived denies all; hidden texts remain readable only to current OWNER/MODERATOR under existing group policy. DM checks both ACTIVE/verified users, existing Exchange opt-in/preferences/language/contact eligibility, canonical CONNECTED pair and no either-direction block through existing lockMessagingPair. Parent/body/context ownership remains unchanged. No third participant or group messaging expansion.

## API and state protocol

Existing /api/v1 prefix, success/error envelope, normal session/access-token checks and cookie CSRF on writes. No new auth flow. Read endpoints permit anonymous only for currently public-eligible Community parents; an invalid supplied identity never downgrades to anonymous. Foreign/missing/revoked object and metadata use opaque404. Anonymous mixed public/private read routes return the same404 for absent or nonpublic objects; protected-write/status routes require authentication before object lookup and return401 consistently for any ID. Invalid supplied credentials return401 before lookup, never an anonymous fallback; normal validation400/413/415, conflicting replay/state409, rate429, temporary provider/processor unavailable503. Never serialize keys, provider endpoints, signed URLs, raw processor stderr or sensitive filenames to logs/errors.

| Route | Request and response contract |
|---|---|
| POST attachments | Strict initiate DTO: clientUploadId(UUIDv4), typed scope, filename, MIME, exact byte count, caption/alt. Returns id/state/expiry plus bounded authenticated upload route; idempotency key is actor+clientUploadId and immutable request fingerprint |
| PUT attachments/:id/content | One raw file stream, declared MIME matches reservation; actual bytes must equal reservation and remain within format cap. No base64/multipart/remote URL. Temporary generated key uses conditional create; ownership/version metadata prevents collision/replacement. Failed/interrupted upload cannot become READY |
| POST attachments/:id/finalize | Same actor/scope; durable HEAD/checksum/size, conditional lease and quarantine inspection. Returns sanitized pending/ready/rejected status; concurrent/repeated finalize cannot duplicate processing. Recheck scope/generation after processing and before READY/binding; deletion/revocation wins |
| PATCH attachments/:id/metadata | Uploader plus fresh intended scope, unbound nondeleted draft only; strict caption/alt and expectedMetadataVersion. Bytes/filename/scope stay immutable. Store original initiation fingerprint separately so identical initiation replay returns current safe metadata without a second reservation. Bound metadata changes use only the authorized Community parent-edit transaction; group/DM after-send metadata edits reject |
| GET attachments/:id | Sanitized status/metadata; draft uploader+fresh scope only, bound current parent ACL; no former filename on removed/unavailable response |
| GET/HEAD attachments/:id/content or /preview | Bound nondeleted READY normalized artifact only; fresh exact domain ACL/state check on every full/HEAD/single-range request. TXT preview unsupported. Multiple/invalid ranges reject; no provider redirect |
| DELETE attachments/:id | Uploader+current domain authority; idempotent opaque deletion response; commit tombstone then physical cleanup. A former member/participant cannot use ownership to regain metadata or mutate retained content |

State machine TEMPORARY -> UPLOADING -> PENDING -> READY or REJECTED, with any live state -> DELETED terminal. Durable object reception must precede PENDING; validated normalized source/thumbnail existence/checksum must precede READY. Same payload retry does not create new object/binding. Conflicting upload bytes cannot replace a completed upload. Expired upload leases use new immutable attempt keys; late PUT completion cannot restore state. Job attempts and known key manifest allow delayed objects to be reconciled. No success persistence/progress assertion before actual storage response. Tombstone, lease/version and ACL rechecks prevent deletion racing finalize from publishing late derivatives.

## Validation and processing boundary

The extension/declared MIME/signature/detected parser format must agree. Canonical JPEG/PNG/WebP framing includes bounded complete-container parsing, terminal marker/chunk lengths/checksums where defined and rejection of appended/trailing payload or multiple images/animation. JPEG is8bit baseline SOF0 with1or3components; SOI/EOI/SOF0/SOS/DQT/DHT/DRI/restart markers only, plus JFIF APP0, EXIF/XMP APP1, ICC APP2, Adobe APP14 and comment segments that are bounded and discarded; other coding/APP markers reject. PNG is8bit/static, color types0/2/3/4/6, exact IHDR/PLTE/tRNS/contiguousIDAT/IEND ordering and CRC32; optional pHYs/sRGB/gAMA/cHRM/iCCP/eXIf/tEXt/zTXt/iTXt discarded without application decompression, animation/unknown chunks reject. WebP requires exact RIFF/WEBP length, one VP8 or VP8L image with optional consistent VP8X/ALPH and bounded EXIF/XMP/ICCP chunks stripped; ANIM/ANMF/unknown chunks reject. Metadata aggregate<=256KiB and each declared chunk/segment within remaining input; no trusting metadata dimensions before full decode. These are initial narrow TEST subsets; progressiveJPEG,16bitPNG and animation remain unsupported. Full decoder warnings/corruption reject. Strip supplied EXIF/GPS/XMP/ICC/private metadata by rotation/color conversion and re-encoding without metadata; verify normalized and thumbnail outputs. Raw originals never inline/download. This is structural/type validation and normalization, not proof that files are malware-free or every conceivable polyglot is recognizable.

MP4 requires complete bounded box traversal with maximum depth8/256boxes, positive32bit box sizes covering exact parent/file length, no size0/extended-size/trailing bytes. Major brand isom and compatible brands limited to isom/iso2/avc1/mp41; ftyp first, exactly one moov and one mdat, at most one empty8byte free box. moov permits mvhd, one or two trak and optional udta; trak permits tkhd/edts(elst)/mdia; mdia permits mdhd/hdlr/minf; minf permits vmhd or smhd, dinf(dref) and stbl. stbl permits stsd/stts/stss/stsc/stsz/stco and audio-only sgpd/sbgp for roll recovery, all with exact bounded lengths/counts and index validation. Video stsd contains exactly one avc1 with avcC/pasp/btrt children; audio exactly one mp4a with esds/btrt. dref contains exactly one self-contained url entry(flags1,noURLpayload), sample-entry reference index1. Offsets and samples must fall entirely inside mdat without overlap/out-of-bounds; video<=360samples, audio<=720samples; track IDs unique, one vide handler and optional soun handler. Encoded video presentation timestamps must be constant-frame-rate and span<=15seconds; no edit outside the media bounds. Input optional udta is limited to <=16KiB of meta(hdlr/ilst with fourcc bytes A9 6E 61 6D (name), A9 63 6D 74 (comment), A9 74 6F 6F (tool) text data atoms) and loci location; these are discarded, never copied. Output permits only server-generated known encoder-tool metadata, never supplied title/comment/location. Unknown boxes, external/encrypted/fragmented/UUID/data-reference/extra-track structures reject. AVC input NAL types only1/5/6/7/8/9 with bounded avcC/sample lengths, constrained-baseline profile66 and yuv420p; strip ALL type6SEI units, preserve only decoded-approved1/5/7/8/9. Extra SPS/PPS/dimensions/profile changes reject. No unreviewed box/codec allowlist expansion in implementation. Strict probe validates actual profile/pixel format/streams/rates/duration and dimensions; full decode with fatal errors before derivative generation, metadata/chapter stripping and reviewed removal of unapproved codec supplemental data. A remux alone is not a promise to erase every in-band metadata payload. If output cannot be shown to meet the frozen sanitization policy, video remains disabled; never serve the original as a fallback. Synthetic supplied-metadata and complex-video evidence must establish the selected transformation before video approval.

TXT has no unique magic signature; strict complete fatalUTF8 structural validation plus exact text/plain/.txt contract is required. Before acceptance, deny recognizable foreign signatures: after the optional BOM, PDF %PDF- (case-insensitive), ZIP bytes50 4B 03 04 /50 4B 05 06 /50 4B 07 08, PE bytes4D 5A and ELF bytes7F 45 4C 46; after leading ASCII SP/TAB/CR/LF, deny case-insensitive HTML doctype/html/script opening tags, SVG opening tag, XML declaration and shebang hash-exclamation. Matching is anchored with proper tag boundaries and bounded by64KiB input; it is not a general document/markup classifier.002 must execute renamed ASCII PDF/HTML/SVG/XML/shebang plus binary-signature negatives, including BOM/leading-whitespace variants. The14processor feasibility cases do not prove this classification. Ordinary UTF8 code/markup-like text without a recognized signature can remain inert .txt download; neither denylist nor validUTF8 is malware-free or exhaustive script identification. It does not turn markup or executable-looking text into trusted content: always attachment/octet-stream download, no document viewer, no HTML rendering, no content sniffing.

Use vetted pinned sharp0.35.5 and checksum-pinned LGPL FFmpeg/ffprobe only after deployment packaging verifies actual versions/source/license notices. Separate child process, generated allowlisted local paths, scrubbed environment, no shell, protocols file/pipe only, no input-controlled options, network protocols disabled, bounded output/stderr/threads/time/temp files. Do not claim process/network sandboxing from a timeout or ffmpeg max_alloc alone. Render cannot provide Docker-style per-job cgroups; exact TEST process-memory watchdog and aggregate API interference probes are enablement gates. If isolation/resources are inadequate, hold the format and retain fail-closed state; no new infrastructure/paid processor.

Moderation is an internal post-validation policy port: the selected local structural/type/domain policy is explicit, not an antivirus or staffed moderation claim. If an enabled moderation hook rejects, times out or is unavailable, stay quarantined/rejected; never fail open. No external moderation/processing service is activated by this contract.

## Privacy, response and revocation

No provider-signed private GET URL, public r2.dev/custom-domain URL or independent bearer ticket. All derivatives inherit live parent ACL. Cache-Control private,no-store; Vary correct auth/cookie semantics; nosniff; image/webp and video/mp4 inline only for validated derivatives, TXT application/octet-stream attachment with server-safe filename plus correctly encoded filename*. No original filename used as a path/header fragment. CSP/object restrictions remain. No public directory, public search/notification media snippets or Library promotion.

Authorization linearizes at current domain+binding/state selection under locks before response admission; revalidate fresh session at admission using existing session checks. Future read/range/preview/metadata requests after committed revoke/deletion deny. Release SQL locks before bounded network transfer. Already admitted/in-flight bytes and downloaded copies cannot be recalled. Signed URL expiration would only limit later use of that URL, not cached/downloaded copies or necessarily started transfers; such private provider URLs are deliberately absent. UI aborts and purges blobs/objectURLs on access/identity loss and discards late responses by generation; client clearing is not backend authorization.
