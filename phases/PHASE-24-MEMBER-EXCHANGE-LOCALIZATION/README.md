## Objective
Extend the existing vi/en product UI from the shared shell/public Library into the connected member journey: authentication, onboarding/language profile and finding a language-exchange partner.

## Scope after explicit authorization
Domain-owned vi/en catalogs and approved error/accessibility copy for existing auth, onboarding/profile language controls, exchange browse and partner detail states. Reuse browser-only locale persistence, Intl formatting and vi fallback. Preserve content/learning-language, session and URL independence.

## Out of scope
Redoing shell/Library/foundation, translating the entire product, third locale, learning-content translation, changed legal terms, provider email/translation APIs, server locale profile/schema and locale-prefixed URLs.

## Entry gate
Separate Phase 24 owner authorization; bounded copy inventory/terminology; consent/legal copy ownership; existing locale/API contract review. This planning dossier is not execution authorization.

## Exit gate
Catalog completeness, safe error mapping, locale switching/reload, learning-language/session/URL independence, a11y/long-copy/responsive runtime and relevant auth/navigation/exchange regressions pass. English human-review status must be truthful; technical completion is not human certification.
