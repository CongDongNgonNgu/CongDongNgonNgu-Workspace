# Phase 06 — Corrections & Q&A

## Goal
Turn community help into structured, reusable learning value. Users can request corrections or ask language questions; qualified community responses can be voted/accepted and later promoted to the Open Language Library through review.

## Core data intent
Corrections preserve `original`, `corrected`, explanation, language, optional level/context, author/reviewer, votes/helpfulness and acceptance/review state. Q&A preserves accepted answer and useful-answer signals separately from generic comments.

## Principle
A correction is not automatically “truth”. Acceptance by the requester and verification for Library reuse are distinct concepts.

## Completion gate
Correction/Q&A creation, inline diff, acceptance/voting, reviewer signals and Library-candidate handoff work with authorization and abuse controls; UI passes Stitch/responsive/a11y; tests/commits/CI complete.
